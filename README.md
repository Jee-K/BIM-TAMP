# BIM-TAMP

Task and motion planning for robotic disassembly using BIM-derived component
geometry and removal groups. The simulator uses a Husky base, UR5e arm and
Robotiq Hand-E gripper. Planning uses PDDLStream, Fast Downward and PyBullet.

## Setup

Tested on Ubuntu 22.04 with Python 3.11. Install a C++ compiler, Make and CMake,
then run from the repository root:

```bash
conda create -n bimtamp python=3.11 pip -y
conda activate bimtamp
python -m pip install -r requirements.txt
python downward/build.py release -j2
```

The robot URDF (`examples/pybullet/tamp/full_robot.urdf`) and its required mesh
files (`models/`) are included. No separate robot asset download is needed.
`models/ASSET_MANIFEST.json` records the filenames and hashes used by the
experiments. Changing collision meshes can change experiment results.

## Experiments

Activate the environment with `conda activate bimtamp` before running the launcher. Alternatively, set
`BIM_TAMP_PYTHON` to the interpreter's absolute path.

Check the inputs without starting planning:

```bash
./run_100_experiments.sh --examples corner floor8 --runs 1 --prepare-only
```

Run a pilot by setting `--runs 1`. For 100 fixed attempts per example:

```bash
./run_100_experiments.sh --examples corner floor8 --runs 100 \
  --max-time 600 --touch-cap 3 --base-planners birrt \
  --task-planner ff-lazy --algorithm adaptive --mppi off --clutter 0
```

This runs 200 trials. In staged mode, the search time limit applies separately
to each removal group. The runner defaults to 300 seconds unless overridden.
Use `--help` for all options. Pilot a new planner/algorithm combination before
launching a campaign; accepted options are not all validated combinations.

Each campaign saves its code snapshot, inputs, configuration, logs, plans and
CSV/JSON summaries under `examples/pybullet/tamp/results/`. Resume with:

```bash
./run_100_experiments.sh --resume /absolute/path/to/campaign
```

Resume uses the saved configuration and skips completed trial IDs. Use a new
campaign directory to change options or repeat completed failures.

## Inputs

`examples/pybullet/tamp/scenes/examples.json` registers two examples:

- `corner`: `corner_2_7col.json`, an 11-member corner example.
- `floor8`: `floor8.json`, an eight-member floor example.

The floor input includes member geometry, targets, workspace, robot start and
placement settings in an optional `simulation` section. Both examples use the
same scene-manifest schema. Corner target areas and workspace are generated by
the shared loader. A shared schema does not imply that every instance was
converted from an IFC file; `source_ifc` records an IFC source when one exists. The floor example can be omitted by deleting `floor8.json`; its preset
then disappears automatically. Neither instance is embedded in the planner.

Use an unregistered scene directly:

```bash
./run_100_experiments.sh --scene /path/to/scene.json --runs 100 --max-time 600 --touch-cap 3
```

Convert an IFC model to a manifest:

```bash
python IFC2SIM/ifc2sim.py --ifc /path/to/model.ifc --output /path/to/scene.json
```

Use `--select-ifc-types` for interactive type selection. Add `--require-ifc-ranks`
only when selected members have `Pset_DeconTAMP.RemovalGroup` and `RemovalRank`.
Without it, the converter can infer ranks from geometric contacts. The simulator
builds its own contacts from box geometry. Contacts and ranks are modeling
assumptions, not structural stability guarantees. Original IFC files are not
included.

## Code map

Paths below are relative to `examples/pybullet/tamp/` unless otherwise stated.

| File | Purpose |
|---|---|
| `planner.py` | Staged search, command execution and saved plans |
| `scene_loader.py` | Scene construction from IFC and JSON inputs |
| `planning/domain.pddl` | Actions, predicates and group/slot rules |
| `planning/streams.pddl` | Stream declarations |
| `planning/problem.py` | Instance facts and placement slots |
| `planning/stream_bindings.py` | Pose, grasp, IK, base-motion and collision streams |
| `robot_geometry.py`, `placement_layout.py` | Robot grasp/contact geometry and placement layouts |
| `run_100_experiments.py`, `experiment_worker.py` | Repeated experiments and isolated workers |
| `run_statistics.py`, `motion_metrics.py` | Diagnostics and trajectory-cost reporting |
| `replay_plan.py`, `audited_replay.py` | Saved-trajectory replay and collision checks |
| `scene_manifest.py` | Planner-side IFC/manifest reader |
| Root `IFC2SIM/ifc2sim.py` | Standalone converter |

The inherited `examples`, `pr2` and `create_pr2` names support existing helper
imports; the loaded robot is defined in `full_robot.urdf`. Local modifications to
PDDLStream and the simulation helpers are retained.

The distance search objective uses straight-line base XY distance plus unit
manipulation costs. Actual base trajectory cost and weighted arm joint-path
length are reported separately; they do not feed back into search. Default
search stops at the first solution. `--search-mode anytime` requests continued
search using the best symbolic cost as its bound, within the configured limits.

## Replay and checks

```bash
python examples/pybullet/tamp/replay_plan.py /path/to/plan.json --speed 2
```

Replay needs a graphical desktop unless `--headless` is supplied. `--audit`
collects collision failures instead of stopping at the first one.

```bash
cd examples/pybullet/tamp
python -m unittest test_bim_tamp -q
python check_ordered_symbolic.py
python check_ordered_geometry.py
```

The tests cover statistics, cost reporting, placement rules and a stored
self-collision configuration. Search success and these checks do not constitute
a physical safety certification.

When working with a coding agent, use this code map, keep changes separate from
saved campaign snapshots, preserve the collision/contact assumptions, and run the
relevant checks before launching new experiments. Source revisions and file hashes
are recorded in `SOURCE_PROVENANCE.json`.
